# RAG Poisoning and Retrieval Security Benchmark

**IBM SkillsBuild Cyber Security BootCamp 2026 · BharatCares**
**Author:** SINDHU SHEKAR

A small, fully local RAG app plus a benchmark that **quantifies** how poisoned knowledge-base documents change a RAG system's behaviour, instead of just demoing a single prompt injection.

## Project description

A RAG system retrieves documents and feeds them to a language model. If an attacker plants a malicious or misleading document, the system can retrieve it and be manipulated. This project:

1. Builds a controlled corpus of **trusted** and **adversarial** documents (misinformation, hidden prompt injections, keyword-stuffed bait, irrelevant spam).
2. Measures **retrieval of irrelevant or malicious content**.
3. Tests whether the model **follows instructions hidden in untrusted documents**.
4. Compares mitigations: **source validation**, **retrieval filtering**, **prompt hardening**, and combinations.
5. Sweeps attack strength (poison volume) and attacker **source-label spoofing**.

### Headline results (mean of 5 seeds, 36 queries each)

| Condition | Poison retrieval | Injection success | Answer accuracy |
|---|---|---|---|
| Clean baseline | 0.0% | 0.0% | 100.0% |
| Poisoned, no defence | 100.0% | 26.7% | 36.1% |
| + Source validation | 83.3% | 30.0% | 51.7% |
| + Retrieval filtering | 94.4% | 18.9% | 36.7% |
| + Prompt hardening | 100.0% | 5.0% | 37.8% |
| Source validation + filtering | 49.4% | 9.4% | 74.4% |
| All three defences | 49.4% | 2.8% | 80.0% |

No single defence is enough; defence in depth helps most but leaves residual risk (mainly convincing misinformation).

## Technologies used

Python 3.10+, NumPy, pandas, scikit-learn (TF-IDF + truncated SVD as the local embedding model), matplotlib, Jupyter. Optional: sentence-transformers (MiniLM) and ChromaDB.

## Dataset

**No external dataset is used.** The dataset is *synthetic and generated by the notebook*: a fictional company ("Northwind Tech") with 12 security-policy topics, 34 trusted documents, up to 36 adversarial documents and 5 spam documents, plus 36 benchmark questions with known ground truth. ## Key information

* **Generator is simulated.** The LLM is a deterministic, instruction-following simulator with documented assumptions (susceptibility 0.85, prompt hardening reduces it to 15%). Results show *relative* effects of attacks and defences, not the behaviour of any specific commercial model. Section 9 of the notebook shows how to plug in a real model (e.g. Ollama).
* **Reproducible:** fixed seeds `[11, 22, 33, 44, 55]`; results reported as mean ± std.
* **Metrics:** Poison Retrieval Rate, Poison Context Share, Irrelevant Context Share, Evidence Recall, Injection Success Rate, Misinformation Rate, Answer Accuracy.
* **Limitations:** synthetic English corpus, lexical embedder by default, non-adaptive attacker.
* **Ethics:** all attack content is harmless and fictional (`example` domains only); the project is for defensive learning.
